# Lessons ledger

**Read this before starting fleet-wide, credential, or monitoring work.** It is the durable record
of what previous sessions learned the expensive way — findings whose rediscovery costs hours, and
which are not obvious from the code they concern.

This is not a changelog and not a design doc. Every row is something that **surprised somebody**,
with a link to the evidence and a note about which tier is holding it.

## The pattern underneath

Nearly every lesson below is the same shape: **a check exists, and it is not checking.** Dead
trigger, dead credential, swallowed 403, presence-mistaken-for-validity, crashed-suite-looks-green.

The generalization is worth stating on its own, because it predicts new instances:

> **"The check is configured" and "the check works" are different claims, and only the second one
> counts.** Verification means observing the thing do its job — not observing that it is enabled.

A corollary that has caught real defects: **a monitor's first report is not evidence the monitor
works.** When a new checker's debut finding is "several things are broken," verify against an
independent signal before anyone acts on it (L03).

## How a tier is chosen

| Tier                     | When                                                          |
| ------------------------ | ------------------------------------------------------------- |
| **CI test / hook**       | the lesson is mechanically detectable in the tree             |
| **Workflow guard**       | the lesson is about runtime behavior a workflow can assert    |
| **`doc —` (prose only)** | genuine judgement, or an external fact no local check can see |

Push each lesson to the **strongest tier that can hold it**. A `doc —` cell must say _why_ prose is
the ceiling; "nobody got round to it" is a gap, and gaps get a linked follow-up issue rather than a
silent prose entry.

## Adding a lesson

Append a row to the matching table. `tests/workflow-logic/test_lessons_ledger.py` enforces the
contract, so a malformed or unenforceable row fails CI:

- **ID** — `L##`, unique, never renumbered **once merged** (merged IDs are cited from issues and
  PRs). An ID in an open PR is only a _reservation_: concurrent drafts routinely pick the same next
  number, and whichever merges first owns it. Before promoting a ledger PR, re-check `main`'s
  highest ID and renumber your own rows if they collide — then assert `uniq -d` over the IDs,
  because a merge that resolves the table cleanly can still leave a duplicate (L43).
- **Lesson** — the transferable claim, not the incident. "Presence ≠ validity" travels; "repo X had
  a stale lockfile on the 24th" does not.
- **Evidence** — an issue/PR/run reference (`#123`) or a URL. A lesson with no evidence link is a
  rumour.
- **Enforced by** — backticked repo path(s) that hold the lesson, **or** `doc — <reason>`. Paths are
  checked for existence: a ledger that claims enforcement which is not there would be this
  document's own failure mode, one level up.

Add the row in the **same PR as the fix**, while the surprise is still fresh.
